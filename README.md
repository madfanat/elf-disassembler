# **Задание**

Необходимо написать программу-транслятор (дизассемблер), с помощью которой можно преобразовывать машинный код в текст программы на языке ассемблера RISC-V.  
Должен поддерживаться набор команд: RV32I и RV32M (LE): [https://github.com/riscv/riscv-isa-manual/releases/tag/riscv-isa-release-6cd14db-2026-05-17](https://github.com/riscv/riscv-isa-manual/releases/tag/riscv-isa-release-6cd14db-2026-05-17)  
Входные данные подаются в ELF-файле. Обрабатывать нужно только секции .text, .symtable.  
Аргументы программе передаются через командную строку:  
**\<имя\_входного\_elf\_файла\> \<имя\_выходного\_текстового\_файла\>**  
Для каждой строки кода указывается её адрес в hex формате.  
Заданные метки нужно найти в Symbol Table (.symtab). Если же название метки там не найдено, то используется следующее обозначение: L%i, например, L2, L34. Нумерация начинается с 0\. Для каждой метки перед названием указывается адрес. Когда в коде кто-то захочет перейти на определённый адрес, у которого нет названия, то тогда ставим метку L%i.  
Например, есть следующая строка:  
   100fc:  fea794e3        	bne  a5, a0, 100e4 \<mmul+0x38\>  
В bne указан переход на адрес, для которого не задано название. Значит на адрес 100e4 назначается метка (например, L0):  
bne a5, a0, L0 ; 0x100e4

## **Шаблон файла дизассемблера**

Файл должен состоять из двух частей: .text и .symtab, отделенных друг от друга одной пустой строкой. Сначала идет .text, затем .symtab.  
Ниже приведены комментарии (строки, начинающиеся с ;) и форматы оформления. Вывод имён регистров: ABI.

Если во входном файле встречается команда, которая не распознается программой, то её следует выводить как unknown\_instruction.  
Псевдоинструкции не распознавать.

# **Работоспособность**

	Неотъемлемая часть работы – подготовка elf-файла, которая будет демонстрировать работоспособность вашей программы.  
	Для этого вы самостоятельно готовите файл my\_test.elf, который будет содержать все поддерживаемые вами инструкции.  
	Ваш подготовленный файл my\_test.elf будет использоваться в автотестах.  
	**Отчётность**  
	Вы должны запустить и успешно пройти автотесты. Без их запуска вашу работу смотреть не будут.  
	Процесс сдачи и защиты этой работы:

1. Самостоятельное выполнение работы (изучение теории, написание кода, …);  
2. Подготовка тестового файла my\_test.elf и проверка работоспособности на нём;  
3. Загрузка работы в репозиторий с последующей проверкой на автотестах;  
4. После успешного прохождения автотеста вы отправляете работу на проверку через форму и не дожидаясь ответа проверяющего можете записываться на защиту;  
5. На защите будет проверяться ваш код и ваши знания. В рамках защиты вас могут попросить распарсить двоичный файл (простой) как это сделала бы ваша программа с объяснением происходящего или написать код на RISC-V, который реализует небольшой алгоритм.
